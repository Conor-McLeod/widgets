Training a neural network means nudging millions of numbers so a loss goes down. To know which way to
nudge each one, you need the derivative of the loss with respect to every one of them. Nobody writes
those derivatives by hand. So how does the computer get them?

There are three ways to get a derivative out of a computer:

- **Symbolic**: apply differentiation rules to the formula, like a computer algebra system. It's exact,
  but the expressions grow quickly, and it needs a formula. A program with loops and `if`s isn't one.
- **Numeric**: evaluate the function twice and take the slope, (f(x+h) − f(x)) / h. It's easy, but
  inexact, as the chart below shows.
- **Automatic**: run the program and apply the chain rule to each operation as it happens. The result is exact
  up to floating-point rounding, and it costs a small constant multiple of running the program.

## Why not just take the slope?

The derivative of sin at x = 1 is cos 1. The chart shows how far two finite-difference estimates land
from it as the step h shrinks. Move along the chart to see the digits.

<Widget src="finite-diff" height={420} caption="Error of finite-difference estimates of sin′(1), on log–log axes." />

From the right, the error falls as h shrinks. That's **truncation error**: a secant line only
approximates the tangent. Somewhere around h = 10<sup>−8</sup> the error turns and starts climbing again.
That's **rounding error**. f(x+h) and f(x) agree in almost every digit, so subtracting them leaves only
a few significant bits, and dividing by a tiny h magnifies the noise. (The [float64](/float64) page shows
why those bits run out.) The best forward difference is right to about 8 digits, and the best central difference to about 11.
A float64 holds about 16.

There's also a cost problem. A loss with a million parameters needs a million and one evaluations to
estimate its gradient this way.

## A program is a chain of tiny functions

Automatic differentiation starts from the fact that any numeric program, however tangled, executes as a
sequence of elementary operations: `+`, `×`, `sin`, `ln`. We know the derivative of each one. Here's the
standard example from Baydin et al., *Automatic differentiation in machine learning: a survey*:

> f(x₁, x₂) = ln x₁ + x₁x₂ − sin x₂

Written as an **evaluation trace**, one operation per line, it becomes the graph below. Each intermediate
v<sub>i</sub> gets a name. The chain rule says that if you know how fast each argument of an operation is
changing, you know how fast its result changes:

> v̇ = Σ (∂v/∂a) · ȧ, summed over the arguments a

## Forward mode: carry the derivative along

Pick one input, say x₁, and pin its **tangent** ẋ₁ = 1 (and ẋ₂ = 0). Then, as each value is computed,
compute its tangent next to it using the rule above. By the time you reach y, ẏ is ∂y/∂x₁.

<Widget src="trace" height={560} />

Step through it. Each step needs only things you've already computed: the argument values, their tangents,
and a local derivative from a lookup table. Nothing is ever written down symbolically, so loops and
branches are fine. The tangent just follows whichever path the program actually takes.

Then switch the seed to x₂. You get ∂y/∂x₂, but only by running the whole pass again. **Forward mode gives
one input's influence on every output per pass.** For a function of n inputs, the full gradient takes n
passes, the same scaling as finite differences without the error.

Forward mode is easy to implement with **dual numbers**: replace each number with a pair (value, tangent)
and overload the arithmetic.

```ts
type Dual = { v: number; d: number };
const mul = (a: Dual, b: Dual): Dual => ({ v: a.v * b.v, d: a.d * b.v + a.v * b.d });
const sin = (a: Dual): Dual => ({ v: Math.sin(a.v), d: Math.cos(a.v) * a.d });
```

## Reverse mode: ask the question backwards

Forward mode asks "if this input moves, how does everything move?" Reverse mode asks the opposite: "how much
does the output care about each value?" That quantity is the **adjoint**, v̄ = ∂y/∂v. The output cares about
itself exactly once, so ȳ = 1. Then the chain rule runs the other way. Each operation passes its adjoint back
to its arguments, scaled by the local derivative:

> ā += v̄ · ∂v/∂a, for each argument a of v

The `+=` matters. A value used in two places, like x₁ (inside both ln and ×), collects a contribution from
each use.

Switch the widget above to **Reverse mode**. It first runs an ordinary forward pass and keeps every value,
because the local derivatives need them. Then it seeds ȳ = 1 and sweeps back. Faded adjoints are still
waiting for contributions. Solid ones are final. Notice what you get at the end: ∂y/∂x₁ *and* ∂y/∂x₂, from
one backward pass. The numbers match the forward-mode results.

**Reverse mode gives every input's influence on one output per pass.** That's the asymmetry that matters.
A loss function has one output and possibly billions of inputs, so reverse mode computes the whole
gradient for roughly the cost of a couple of forward passes. The price is memory: the forward values (the
**tape**) have to be kept until the backward pass uses them.

## Backpropagation is reverse mode on a network

A neuron is just another evaluation trace. Here's one tanh neuron with two inputs, a target t, and a squared
error loss:

> L = (tanh(w₁x₁ + w₂x₂ + b) − t)²

It's the same widget with a different graph, starting in reverse mode. Step through the backward pass and
watch L̄ = 1 flow back through the square, the subtraction, the tanh and the sums until it reaches the
weights. The adjoints w̄₁, w̄₂ and b̄ are the gradient. **Gradient step** moves each weight a little
against its gradient. Press it a few times and L drops toward zero.

<Widget src="neuron" height={640} />

That's backpropagation. The name comes from neural networks, but the algorithm is reverse-mode automatic
differentiation applied to a loss. Nothing in it is specific to neurons. Libraries like PyTorch and JAX
record a tape of operations as your code runs and sweep it backwards when you call `backward()` or
`grad`.

The whole engine fits on a screen. Each `Value` records its parents and its local derivatives. `backward()`
puts the tape in topological order, seeds the output with 1, and applies `ā += v̄ · ∂v/∂a` from the end.

```ts
class Value {
  grad = 0;
  constructor(public data: number, public parents: Value[] = [], public local: number[] = []) {}

  add(b: Value) { return new Value(this.data + b.data, [this, b], [1, 1]); }
  mul(b: Value) { return new Value(this.data * b.data, [this, b], [b.data, this.data]); }
  tanh() {
    const t = Math.tanh(this.data);
    return new Value(t, [this], [1 - t * t]);
  }

  backward() {
    const order: Value[] = [];
    const seen = new Set<Value>();
    const visit = (v: Value) => {
      if (seen.has(v)) return;
      seen.add(v);
      v.parents.forEach(visit);
      order.push(v); // parents before children
    };
    visit(this);
    this.grad = 1;
    for (const v of order.reverse())
      v.parents.forEach((p, i) => (p.grad += v.grad * v.local[i]));
  }
}
```

The widget below trains a network with two inputs, one hidden layer of tanh units, and one output, using
exactly that engine. Every training step builds the loss over all 120 points as a fresh tape of
`Value`s, calls `backward()` once, and moves each weight against its gradient. No derivative is written
anywhere by hand.

Press **train** on **xor**. No straight line separates the two colours, so the hidden units have to bend the
boundary. Things to try:

- Switch the edges to **gradients**. Early on they're thick, because the loss is sensitive to almost every weight.
  As the network fits, they thin out. A thick edge late in training points to a weight that's still doing work.
- Drop **hidden** to 2 on **circle**. Two tanh units can only draw two soft lines, which isn't enough to
  enclose a disc, so the loss stalls.
- Push the **learning rate** above 1. The steps overshoot and the loss curve turns jagged. Too small, and
  it barely moves.
- Look at the tape size in the stats line. A few thousand operations are recorded per step, and a
  single backward pass gives all of the gradients at about the same cost as the forward pass.
